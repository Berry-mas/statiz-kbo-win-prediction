# Y-wins KBO Forecast Dashboard

Next.js dashboard for public Y-wins KBO forecast results, submission status,
and manual submit dispatch.

## Data Contract

The app reads `public/results.json`. That file is generated by
`src/public_results.py` and contains only public-safe submitted games, finalized
game results, scheduler summaries, and model operating metrics.

Do not place API keys, raw Statiz API payloads, feature matrices, live schedules,
or unfinalized predictions in this directory.

## UI Contract

- Submitted games are paginated by game date.
- Finalized ledger rows are paginated by game date.
- Game-card dates use `M.D`; operational game dates use `YYYY.MM.DD`.
- Hit/Miss and Accuracy are based on submitted probability.
- Cancelled games are shown but excluded from accuracy.
- Site views and site-level likes are stored in Upstash Redis, not in
  `public/results.json` or local files.

## Site Stats Storage

The dashboard uses the dynamic API route `app/api/site-stats/route.ts` for
page-view and site-like counters. Use Vercel Marketplace Storage with Upstash
Redis for production. The Vercel project root must remain `web/`.

Required environment variables. Vercel Marketplace may create the `KV_*` names;
the route also supports the direct Upstash names.

```bash
KV_REST_API_URL=https://...
KV_REST_API_TOKEN=...

# Also supported:
# UPSTASH_REDIS_REST_URL=https://...
# UPSTASH_REDIS_REST_TOKEN=...
```

Provisioning options:

1. In Vercel, add the Upstash Redis integration from Marketplace Storage and
   connect it to this project so Vercel injects the Redis REST credentials.
2. For local development, copy the same values into `web/.env.local`.

The current scope is `site`, so one global like counter is shown. The API also
accepts a future `scope` value for extending the same storage pattern to
game-level likes later.

## Local Commands

```bash
npm install
npm run dev
npm run build
npm run typecheck
```

For Vercel, set the project root directory to `web/`. The dashboard itself is
static. The optional manual submit API requires `MANUAL_SUBMIT_TOKEN`,
`GITHUB_ACTIONS_TRIGGER_TOKEN`, and related GitHub workflow environment values.
